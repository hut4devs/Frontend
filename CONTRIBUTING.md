# Contributing

1. Pick an issue and confirm acceptance criteria.
2. Create a focused branch, e.g. `feat/123-member-dashboard`.
3. Add or update tests with the implementation.
4. Run type-check, tests, and build checks.
5. Open a pull request linking the issue and explaining user impact and validation.

Use TypeScript at API boundaries; handle loading, empty, error, and success states; keep business rules in the backend; use semantic HTML, keyboard navigation, visible focus, and accessible labels. Never commit secrets or real user data. Use the Hut4Devs 🛖 commit convention where practical.
